# Decisive Experiment Framework

Design the smallest ethical test that can change the decision. Test behavior rather than compliments where possible.

## Experiment contract

Write every experiment as a compact contract:

| Field | Requirement |
| --- | --- |
| Risky assumption | Name the single assumption most likely to invalidate the opportunity. |
| Target audience | Define the segment and how it will be reached. |
| Method | Choose the cheapest credible method: evidence audit, problem interview, concierge offer, landing page, price test, preorder, paid pilot, or retention test. |
| Offer and ask | State what is offered and the observable commitment requested. |
| Time box and sample | Define the deadline and minimum number of qualified observations. |
| Success threshold | Set a numeric or observable result that upgrades or sustains the decision. |
| Failure threshold | Set a numeric or observable result that downgrades, watches, or kills the opportunity. |
| Decision rule | State the exact decision after success, failure, or an inconclusive result. |
| Cost and owner | Keep the test within an explicit budget and accountable owner. |

## Selection rules

- Test the riskiest assumption first, not the easiest feature to build.
- Prefer a deposit, paid pilot, signed commitment, or repeated behavior over survey enthusiasm.
- Keep the test narrow enough that a result is interpretable by segment and use case.
- Do not count vanity metrics as validation unless they predict the stated commitment.
- Pre-commit thresholds before collecting results. If results are inconclusive, state what prevented a decision and choose the next cheapest discriminating test.

## Common decision rules

- **Success:** enough qualified prospects take the requested costly action; upgrade to `GO` or continue a `TEST` with the next risk.
- **Failure:** the threshold is missed, willingness to pay fails, or the chosen alternative remains preferable; downgrade to `WATCH` or `KILL`.
- **Inconclusive:** execution, audience quality, or sample size invalidates the read; repeat only if the next test fixes that defect at low cost.
